# 节点库维护

`library/` 是 Material Pro 自己的节点库源码：节点、示例、节点菜单、笔刷、着色器公共函数、导出模板和翻译都在这里维护。应用加载的 `public/data/` 由它生成，不要手改 `public/data/`。

这些内容最初从 Material Maker 导入（见 [NOTICE.md](../NOTICE.md)），之后与它脱钩：Material Maker 的更新**只作参考**，不会自动同步，也没有补丁机制。想借鉴上游的改动时，按本文最后一节的做法人工比对后再改 `library/`。

## 目录结构

| 路径 | 内容 |
| --- | --- |
| `library/nodes/<type>.json` | 一个节点一个文件，文件名就是节点类型（`type`）。共 399 个 |
| `library/io-types.json` | 端口类型：名称、GLSL 类型、参数、类型转换、颜色 |
| `library/previews/<type>.glsl` | 端口类型的 2D 预览函数（例如 `sdf2d` 怎么画成图） |
| `library/shader-functions.glsl` | 所有着色器共用的函数（随机数、颜色空间、混合等） |
| `library/templates/*.tmpl` | 导出模板（Godot `.tres`、Unity `.mat`、HLSL/GLSL 定义等） |
| `library/menu.json` | 节点菜单（左侧节点库树）：每项的 `tree_item` 路径、节点类型、预设参数、图标 |
| `library/menu-icons/*.png` | 节点菜单图标，`menu.json` 里用 `icon_file` 引用 |
| `library/aliases.json` | 节点库搜索的别名：菜单路径 → 逗号分隔的关键词 |
| `library/brushes.json`、`library/brush-icons/` | 绘制模式的笔刷和图标 |
| `library/environments.json` | 3D 预览的环境（HDRI、颜色、亮度） |
| `library/examples/*.ptex` | 示例材质（与用户保存的 `.ptex` 格式相同）。共 43 个 |
| `library/locale/<lang>.json` | 界面和节点的翻译：英文原文 → 译文 |
| `library/locale/<lang>.nodes.json` | 节点库自己的字符串的翻译（节点名、参数、端口、说明、菜单路径），同样的格式 |
| `library/LICENSE-material-maker.md` | Material Maker 的 MIT 许可证原文，必须保留 |

生成：

```bash
npm run data
```

它运行 `scripts/build-data.mjs`，写出 `public/data/`：`nodes.json`、`io_types.json`、`templates.json`、`shader_functions.glsl`、`library.json`、`brushes.json`、`environments.json`、`examples/*.json` 和 `locale/*.json`。`npm run dev` 不会自动运行它，改了 `library/` 后要手动运行一次再刷新页面；`npm run build` 会先运行它。

生成时做的转换：

- 节点、示例、笔刷里的代码字段（`code`、`custom`、`global`、`instance`、`preview_shader`、`template`）在库里是**按行拆开的字符串数组**，方便看 diff；生成时用 `\n` 连接成一个字符串。写新代码时也按行写成数组，单个字符串同样可以。
- `icon_file` 读出 PNG，内联成 base64 的 `icon_data`。
- `<lang>.nodes.json` 合并进 `<lang>.json`；同一个键两边都有时以 `<lang>.json` 为准。

## 节点 JSON

一个着色器节点的骨架：

```json
{
	"name": "my_node",
	"type": "shader",
	"node_position": { "x": 0, "y": 0 },
	"parameters": { "scale": 4, "color": { "r": 1, "g": 0.5, "b": 0, "a": 1, "type": "Color" } },
	"seed_int": 0,
	"shader_model": {
		"name": "My Node",
		"shortdesc": "一句话说明",
		"longdesc": "详细说明，可以多行",
		"parameters": [],
		"inputs": [],
		"outputs": [],
		"includes": [],
		"global": [],
		"instance": [],
		"code": []
	}
}
```

顶层字段：

| 字段 | 说明 |
| --- | --- |
| `type` | `shader`（单个着色器节点）、`graph`（由其它节点组成的子图）、`material_export`（材质输出节点，带导出配置） |
| `name` | 节点类型名，与文件名一致 |
| `parameters` | 参数的默认值，键是参数名。放进节点图时这些值会复制到节点上 |
| `seed_int` / `seed` / `seed_locked` | 随机种子。用到 `$seed` 或 `$rnd()` 的节点才有意义 |
| `generic_size` | 可变数量的端口/参数组的初始数量（见“可变数量的端口”） |
| `nodes`、`connections`、`label`、`shortdesc`、`longdesc` | `graph` 类型：子图里的节点、连线、显示名和说明 |
| `export` | `material_export` 类型：各导出目标的文件和模板 |

### `shader_model`

| 字段 | 说明 |
| --- | --- |
| `name` | 显示名（节点标题）。翻译键 |
| `shortdesc` / `longdesc` | 简短 / 详细说明，显示在节点库和检查器中。翻译键（多行时可以整段翻译，也可以逐行翻译） |
| `parameters` | 参数列表，见下文 |
| `inputs` | 输入端口列表 |
| `outputs` | 输出端口列表 |
| `includes` | 依赖的其它节点的 `global` 代码，写节点类型名，例如 `["blend", "adjust_hsv"]`。被包含的节点的 `global` 只会插入一次 |
| `global` | 全局代码：函数定义等。同一种节点无论用几次只插入一次，所以不能引用参数 |
| `instance` | 每个节点实例一份的代码：可以使用 `$name`、参数和输入。定义的函数名应包含 `$(name)` 以免冲突 |
| `code` | 每次求值时插入到调用点的代码（在 `main` 里），一般用来计算会被多个输出共用的中间变量，变量名用 `$(name_uv)` 开头 |
| `custom` | 少数节点自定义的额外代码（引擎按节点特殊处理） |
| `exports`、`preview_shader` | 材质节点：导出目标定义和 3D 预览着色器 |

#### 参数

每个参数都有 `name`（代码里用 `$name` 引用）、`label`（显示名，翻译键）、`type`、`default`，可选 `shortdesc`、`longdesc`。`label` 可以写成 `"2:Scale"`，冒号前的数字决定它在节点上显示的行（与某个输入端口对齐），翻译时只取冒号后面的部分。

| `type` | 其它字段 | 代码中的值 |
| --- | --- | --- |
| `float` | `min`、`max`、`step`，可选 `control`（2D 预览上的控制点，如 `"P1.x"`、`"Angle1.a"`、`"None"`）、`widget`（如 `"spinbox"`） | `float` 字面量；也可以填表达式（见用户手册“参数与表达式”） |
| `size` | `first`、`last`（2 的幂的指数范围，例如 9–12 表示 512–4096） | 像素尺寸 |
| `enum` | `values: [{ "name": "显示名", "value": "代码片段" }]` | 选中项的 `value` 原样替换进代码 |
| `boolean` | — | `true` / `false` |
| `color` | — | `vec4` |
| `gradient` | — | 生成的渐变函数，按 `$name(x)` 调用 |
| `curve` | — | 生成的曲线函数，`$name(x)` |
| `polygon`、`polyline` | — | 点数组和点数常量 |
| `splines` | — | 样条数据 |
| `pixels` | — | 小图像的像素数据 |
| `lattice` | — | 晶格变形的控制点 |
| `string`、`file`、`image_path` | — | 只用于特殊节点（文字、图像） |

`enum` 每个值的 `name` 也是翻译键。

#### 端口

输入端口：`name`（代码里用 `$name(uv)` 采样）、`type`、`default`（未连接时使用的表达式，例如 `"vec4(0.0)"`、`"0.0"`）、`label`、`shortdesc`、`longdesc`，可选 `function: true`（把输入作为函数传入，而不是在调用点求值）、`group_size`。

输出端口：`type` 以及一个与类型同名的键，值是输出表达式，例如：

```json
{ "type": "rgba", "rgba": "vec4($(name_uv)_c, 1.0)", "shortdesc": "Output", "longdesc": "..." }
```

表达式里可以出现 `@NOCODE`（不插入 `code`）、`@KEEPTYPE` 等标记，由引擎处理。

端口类型定义在 `library/io-types.json`：

| 类型 | GLSL | 说明 |
| --- | --- | --- |
| `f` | `float` | 灰度 |
| `rgb` | `vec3` | 颜色 |
| `rgba` | `vec4` | 带 Alpha 的颜色 |
| `sdf2d` | `float` | 2D 有向距离 |
| `sdf3d` | `vec2` | 3D 有向距离（距离、材质 ID） |
| `sdf3dc` | `vec4` | 带颜色的 3D 有向距离 |
| `tex3d_gs`、`tex3d` | `float`、`vec3` | 3D 纹理（灰度、彩色） |
| `fill` | `vec4` | 填充信息（包围盒等），配合 Fill 系列节点 |

类型之间的自动转换写在每个类型的 `convert` 里（例如 `f` → `rgba` 是 `vec4(vec3($(value)), 1.0)`）。新增类型时要同时给出 `paramdefs`、`params`、`convert`、`color`，需要 2D 预览时再加 `library/previews/<type>.glsl`。

### 代码里的 `$` 关键字

| 写法 | 含义 |
| --- | --- |
| `$uv` | 当前采样坐标（`code` 和输出表达式中） |
| `$参数名`、`$(参数名)` | 参数值；`$(...)` 用于紧接字母数字的场合 |
| `$输入名($uv)` | 采样输入端口，坐标可以是任意表达式 |
| `$name`、`$(name)` | 这个节点实例的唯一名字，用来给 `instance` 里的函数和变量命名 |
| `$(name_uv)` | 实例名加当前坐标的唯一名字，用于 `code` 里的局部变量 |
| `$seed`、`$(seed)` | 节点的随机种子（`float`） |
| `$rnd(a, b)`、`$rndi(a, b)` | 每次放置节点时随机的参数值（浮点 / 整数） |
| `$time` | 动画时间（秒） |
| `$node_id` | 节点 ID |
| `$?1`…`$?4` | 受控变体的变量（Controlled Variations 系列节点） |
| `$in.variation(uv, seed)` | 带变体种子采样输入 |
| 全局参数名 | 设置里定义的全局参数（`mm_global_*` uniform） |

### 可变数量的端口（`#`）

名字里带 `#` 的参数和输入是一组可复制的端口，数量由 `generic_size` 决定，用户可以在节点上增减。展开时 `#` 被替换为 1、2、3…，`label`、`shortdesc`、`longdesc` 里的 `#` 也一样。代码中用 `#for` … `#end` 包住每组要重复的部分：

```json
"code": [
	"vec4 $(name_uv)_b = $b($uv);",
	"#for",
	"$(name_uv)_b = mix($(name_uv)_b, $l#($uv), $amount#);",
	"#end"
]
```

输出也可以是可变数量的（输出的 `type` 带 `#`）。翻译时把带 `#` 的原文作为键（例如 `"Layer#": "图层#"`），界面会把“Layer2”按“图层#”显示成“图层2”。

### 子图（`type: "graph"`）

子图由 `nodes` 和 `connections` 组成，和 `.ptex` 文件里的结构相同。其中：

- `ios` 类型的节点（名字 `gen_inputs`、`gen_outputs`）定义子图的输入、输出端口，`ports` 里每项有 `name`、`type`、`shortdesc`、`longdesc`；
- `remote` 类型的节点把内部节点的参数暴露成子图自己的参数：`widgets` 里每项有 `label`、`linked_widgets`（指向内部节点的 `node` 和 `widget`），`configurations` 型的控件把多组参数值存成一个下拉选项。

最方便的做法是在应用里搭好节点图，选中后按 Ctrl+G 打组为子图，在检查器里设置它的端口和参数面板，保存工程，再从 `.ptex` 里把这个子图节点的 JSON 复制出来，整理成 `library/nodes/<type>.json`（顶层加上 `"type": "graph"` 和 `name`）。着色器节点同理：用“编辑 → 编辑节点…”（Ctrl+E）调好着色器模型后，从 `.ptex` 或检查器的“以 JSON 编辑模型”复制。

### `material_export`

材质节点（`material`、`material_raymarching` 等）带导出定义：`exports` 下每个导出目标（Godot、Unity、Unreal、Blender…）有 `files`，每个文件给出文件名、类型（`texture`、`template` 等）和模板或要输出的通道；`template` 字段可以引用 `library/templates/` 里的模板。

## 新增或修改节点

1. 在 `library/nodes/` 新建 `<type>.json`（复制一个相近的节点改最省事），或修改已有文件。文件名、`name` 和菜单里的 `type` 要一致。
2. 要出现在节点库里，在 `library/menu.json` 的 `items` 里加一项：`tree_item`（菜单路径，例如 `"Filter/My Node"`）、`type`、`name`，可选 `parameters`（预设参数，同一个节点可以有多个预设项）、`icon_file`（放进 `library/menu-icons/` 的 PNG，建议 32×32）。搜索别名加到 `library/aliases.json`。
3. 翻译：把节点名、参数和端口的 `label`、`shortdesc`、`longdesc`、`enum` 值、菜单路径的每一段加到 `library/locale/zh.nodes.json`（键是英文原文）。
4. 运行 `npm run data`，在应用里试用。
5. 验证（见下一节）。

修改已有节点时注意兼容旧文件：已保存的 `.ptex` 按参数名存值，删除或改名参数会让旧文件丢掉这个值；`enum` 按序号存，只能在末尾添加选项。

## 新增或修改示例

示例就是 `.ptex` 文件。在应用里做好材质，“文件 → 保存”，把文件放进 `library/examples/`，运行 `npm run data`，它就会出现在“文件 → 示例…”里（列表来自 `public/data/examples/index.json`）。示例用到的节点必须都在 `library/nodes/` 里。

## 验证

```bash
node scripts/check-i18n.mjs
```

列出没有中文翻译的界面字符串和节点库字符串（包括参数、端口没有显示名时显示的内部名，如 `in1_default`），全部翻译后退出码为 0。

```bash
node tests/run-harness.mjs nodes
```

在无头 Chromium 里编译每个节点的每个输出，报告编译失败的节点。

```bash
node tests/run-harness.mjs examples
```

渲染每个示例的每个节点，报告编译或渲染失败。可以只跑指定示例：`node tests/run-harness.mjs examples bricks wood`。

```bash
node tests/run-harness.mjs all
```

依次运行 nodes、examples、exports（每个导出目标）、sdf，任何一项失败退出码为 1。提交节点库的改动前应该跑一次，并同时跑 `npx vitest run`。

## 参考 Material Maker

Material Maker 仍在更新，可以从中借鉴新节点或修正，但**不要整体同步**：本项目的节点可能已经改过，上游的改动也未必适合这里。做法：

1. 克隆一份 Material Maker（任意版本）：

   ```bash
   git clone --depth 1 https://github.com/RodZill4/material-maker.git ../material-maker
   ```

2. 列出差异（只读，不写任何文件）：

   ```bash
   npm run compare:reference -- ../material-maker
   ```

   输出：只在上游有的节点、只在本库有的节点、两边不同的节点（逐字段：`code`、`global`、`instance`、参数增删、输出、子图等）、示例和菜单的差异，以及上游用到而本项目引擎可能还不支持的参数类型、端口类型和节点类型。加 `--json` 输出 JSON，加 `--detail <节点>` 打印某个节点的代码差异。

3. 逐项判断是否采用，手工把需要的内容改进 `library/`（上游是 `.mmg`/JSON5 格式，代码是单个字符串；放进来时按本库的格式整理），补上翻译，然后跑上一节的验证。引擎不支持的新特性要先在 `src/engine` 里实现。

导入时的上游版本记录在 [NOTICE.md](../NOTICE.md)。从上游借鉴的代码仍是 MIT 许可证，保留 `library/LICENSE-material-maker.md` 即可。
