# 本地验证：把导出结果放进真实引擎

CI 只验证 Material Pro 自己：导出的文件齐不齐、格式对不对、尺寸对不对（`npm run test:cli`、`npm run test:e2e`）。导出的材质在 Godot、Blender、Unity、Unreal、Cocos 里是否真的正确，**按设计在你自己的 Mac 上检查**：CI 不安装这些引擎，也不会下载它们。

- Godot 和 Blender 有自动检查脚本（`npm run test:engines`），装了引擎就能跑。
- Unity、Unreal、Cocos Creator、m3e-canvas-pro 没有可靠的无界面导入方式，用下面的手动清单逐项核对。

发现问题时，把“要报告的内容”一节列的东西发回来即可。

## 准备

```bash
npm install
```

```bash
npm run build
```

下面用到的示例导出都用命令行生成（用法见 [命令行.md](命令行.md)）。建议导出两个示例：`bricks`（有法线、高度、遮蔽，没有自发光）和 `lava`（有自发光）。示例工程在 `public/data/examples/*.json`（直接当 `.ptex` 用）：

```bash
mkdir -p ~/mp-check && cp public/data/examples/bricks.json ~/mp-check/bricks.ptex && cp public/data/examples/lava.json ~/mp-check/lava.ptex
```

## 一、自动检查：Godot 4 和 Blender

```bash
npm run test:engines
```

脚本按以下顺序找引擎，找不到就跳过并说明原因，**不会下载任何东西**：

| 引擎 | 查找顺序 |
| --- | --- |
| Godot 4 | 环境变量 `GODOT_BIN` → `PATH` 里的 `godot`、`godot4`、`Godot` → `/Applications/Godot.app/Contents/MacOS/Godot`（或 `Godot_mono.app`） |
| Blender | 环境变量 `BLENDER_BIN` → `PATH` 里的 `blender` → `/Applications/Blender.app/Contents/MacOS/Blender` |

引擎装在别处时指定路径：

```bash
GODOT_BIN=~/Apps/Godot_v4.3.app/Contents/MacOS/Godot BLENDER_BIN=~/Apps/Blender.app/Contents/MacOS/Blender npm run test:engines
```

也可以只跑一个：`node tests/engines/godot-import.mjs`、`node tests/engines/blender-import.mjs`。

**Godot 做了什么**：建一个临时 Godot 工程，用命令行导出 `bricks`、`lava` 的 `Godot/Godot 4 Standard`、`Godot/Godot 4 ORM` 和 `.glb`（256 px），运行 `godot --headless --import` 导入，再用一段 GDScript 加载每个 `.tres` 和 `.glb`，检查：

- `.tres` 能加载，类型是 `StandardMaterial3D` / `ORMMaterial3D`；
- 文件里写的每个属性 Godot 4 都认识（不认识的会被 Godot 悄悄忽略，脚本会报出来），数值、颜色、开关与文件一致；
- 每张贴图指向正确的文件，尺寸是 256×256；
- `.glb` 导入后网格上有材质，albedo、粗糙度（绿色通道）、金属度（蓝色通道）、法线、遮蔽、自发光贴图都在对应的槽位里。

**Blender 做了什么**：用命令行导出 `Blender` 配置和 `.glb`，以后台模式（`blender -b`）运行一段 Python：

- 载入 Blender 配置的每张贴图，检查能解码、尺寸是 256×256、粗糙度/金属度/置换/遮蔽是浮点 EXR；按用途接进 Principled BSDF（albedo → Base Color，rough → Roughness，metal → Metallic，normal 经 Normal Map → Normal，emission → Emission Color，displace 经 Displacement → 材质输出的 Displacement），检查连接都在；
- 用 Blender 自带的 glTF 导入器导入 `.glb`，检查 Base Color、Metallic、Roughness、Normal（经 Normal Map 节点）、Emission 都连着正确尺寸的贴图。

**结果**：每项一行 ✓ 或 ✗，最后是通过和失败的数量。全部通过时退出码为 0，临时文件会删掉；有失败时退出码为 1，并保留临时工程（路径会打印出来）供查看。

## 二、手动清单

每个引擎都按“导出 → 导入 → 核对 → 报告”做。核对时把材质放到一个球或平面上，在有光照的场景里看。

### Unity（3D 内置管线 / URP / HDRP）

导出（按项目的管线选一个）：

```bash
node bin/material-pro.mjs export ~/mp-check/bricks.ptex ~/mp-check/lava.ptex -t Unity/3D -s 1024 -o ~/mp-check/unity3d
```

URP 用 `-t Unity/URP -o ~/mp-check/urp`，HDRP 用 `-t Unity/HDRP -o ~/mp-check/hdrp`。

导入：把整个输出文件夹拖进 Unity 的 `Assets/`（`.meta` 要一起拖进去，它们决定贴图的导入方式和材质对贴图的引用）。

核对：在 Project 窗口选中 `bricks.mat`，看 Inspector。

| 管线 | 着色器 | 槽位 → 文件 |
| --- | --- | --- |
| 3D | Standard | Albedo → `bricks_albedo`；Metallic → `bricks_metal_smoothness`（Source 为 Metallic Alpha）；Normal Map → `bricks_normal`；Height Map → `bricks_height`；Occlusion → `bricks_occlusion`；lava 还有 Emission → `lava_emission` |
| URP | Universal Render Pipeline/Lit | Base Map → `_albedo`；Metallic Map → `_metal_smoothness`；Normal Map → `_normal`；Height Map → `_height`；Occlusion → `_occlusion`；Emission → `_emission`（lava） |
| HDRP | HDRP/Lit | Base Map → `_albedo`；Mask Map → `_maskmap`（R 金属度、G 遮蔽、A 光滑度）；Normal Map → `_normal`；Height Map → `_height`（置换模式为 Pixel displacement）；Emissive Color → `_emission`（lava） |

另外检查：

- 选中 `bricks_normal.png`，Texture Type 应为 **Normal map**；albedo、emission 应勾选 **sRGB**，其他贴图不勾选。Unity 没有弹出“This texture is not marked as a normal map”的修复提示。
- Console 里没有关于材质或贴图的错误；材质不是粉红色（粉红表示着色器没找到，通常是管线选错了）。
- 球上看：砖缝凹陷、砖面有起伏（法线和高度方向正确，不是反的），砖面粗糙不反光，lava 的岩浆部分发光。

### Unreal Engine 5

导出：

```bash
node bin/material-pro.mjs export ~/mp-check/bricks.ptex -t "Unreal/Unreal Engine 5" -s 1024 -o ~/mp-check/ue5
```

得到贴图和 `bricks.py`。这个脚本沿用 Material Maker 的做法，需要 Material Maker 安装目录 `export/` 文件夹里的辅助模块 `mm.py`（Material Pro 目前不附带它）。

导入：

1. 启用插件 **Python Editor Script Plugin**（Edit → Plugins），重启编辑器。
2. 把 `mm.py` 放到 `bricks.py` 所在的文件夹，并把 `bricks.py` 第三行 `sys.path.append(...)` 改成这个文件夹的路径。
3. 在 Output Log 底部把命令行切到 **Python**，运行 `py "~/mp-check/ue5/bricks.py"`（写完整路径）。

核对：Content Browser 里出现材质 `bricks`，贴图在 `/Game/Textures`。打开材质：

- Base Color ← `bricks_albedo` 的 RGB；Metallic ← `bricks_orm` 的 B；Roughness ← G；Ambient Occlusion ← R；Normal ← `bricks_normal`。
- UV 经过 ParallaxOcclusionMapping 节点，高度贴图为 `bricks_height`，Height Ratio 0.05。
- `bricks_orm`、`bricks_height` 的 sRGB 应**关闭**，`bricks_normal` 的压缩设置为 Normalmap。
- 预览球上砖缝凹陷，没有明显的错位或闪烁。

### Unreal Engine 4

导出用 `-t "Unreal/Unreal Engine 4"`，得到贴图和 `bricks.mm2ue`。打开 `.mm2ue`，按文件开头注释里的步骤做（复制模板材质，把着色器代码粘贴到 Custom 节点，再把 albedo、orm、normal、height 等贴图分别指定到图里对应的纹理参数）。核对内容同 UE5。

### Cocos Creator 3.x

导出（两种都试）：

```bash
node bin/material-pro.mjs export ~/mp-check/bricks.ptex ~/mp-check/lava.ptex -t cocos -s 1024 -o ~/mp-check/cocos
```

```bash
node bin/material-pro.mjs export ~/mp-check/bricks.ptex -t glb --glb-shape sphere -s 1024 -o ~/mp-check/glb
```

**材质文件夹**：把 `~/mp-check/cocos/bricks` 整个拖进项目的 `assets/`。在资源管理器里选中 `bricks.mtl`，属性检查器中：

- Effect 为 `builtin-standard`；勾选了 USE ALBEDO MAP、USE PBR MAP、USE NORMAL MAP（lava 还有 USE EMISSIVE MAP）。
- Albedo Map → `bricks_albedo`；PBR Map → `bricks_pbr`（R 遮蔽、G 粗糙度、B 金属度）；Normal Map → `bricks_normal`；lava 还有 Emissive Map → `lava_emissive`。
- Roughness、Metallic、Occlusion 为 1（由贴图决定），Normal Strength 为 1。
- 贴图资源导入时没有报错，`.meta` 里的 uuid 没有和项目里现有资源冲突（控制台没有 uuid 冲突警告）。
- 把材质拖到场景里的球上：效果与 Material Pro 3D 预览一致。

**GLB**：把 `bricks.glb` 拖进 `assets/`，展开后应有网格、材质和贴图。把它拖进场景：球体带着贴图显示，法线方向正确（凹凸不反）。

### m3e-canvas-pro（支持导入后）

导出：

```bash
node bin/material-pro.mjs export ~/mp-check/bricks.ptex -t m3e --name 砖墙 -o ~/mp-check/m3e
```

在 m3e-canvas-pro 里导入 `bricks.m3e-material.json`（格式见 [m3e-material.md](m3e-material.md)）：

- 材质库里多了一个名为“砖墙”的材质，原有材质和工程内容没有被替换。
- 给一张卡片添加 `material` 填充层并选它：“原样”模式显示带光照的砖面，平铺单元在 100% 缩放下约 160 px，接缝处无明显断开；“染色”模式下随主题色变色，切换深浅模式后仍然可读。
- 光从左上方来（方位角 315°，高度 45°）。
- 导出 CSS 或保存后重新打开，材质还在。

## 三、要报告的内容

发现问题时请发回：

1. **哪个引擎、哪个版本**，Unity/Unreal 还要说明管线或模板（如 URP 14、UE 5.4）。
2. **哪个导出目标、哪个示例、什么尺寸**，最好附上完整的命令行。
3. **哪一项不对**：对照上面的清单写出“应该是什么 / 实际是什么”，例如“Metallic 槽位是空的”、“法线凹凸方向反了”。
4. **截图**：Inspector / 属性面板，和材质在球上的样子；最好同时附上 Material Pro 3D 预览的截图做对比。
5. **引擎控制台里的错误或警告**原文。
6. 自动检查的话，`npm run test:engines` 的完整输出，以及失败时保留的临时目录里的文件（Godot 工程或 Blender 的 `check.py` 和导出文件）。
